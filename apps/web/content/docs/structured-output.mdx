Pass a JSON Schema to `agent.run()` and AnyAgent returns the agent’s reply parsed and validated against it, on `RunResult.json`. This page shows how to describe the shape you want, read the parsed value, and handle a reply that never matches. The contract is identical on every supported agent: a validated value on `result.json`, with one retry, whether the reply comes back bare, fenced, or embedded in prose.

## Describe the shape with a JSON Schema

`RunOptions.schema` takes a plain JSON Schema object. This one asks for a repo’s runtime dependencies and its test command:

```ts
const schema = {
  type: "object",
  properties: {
    dependencies: { type: "array", items: { type: "string" } },
    testCommand: { type: "string" },
  },
  required: ["dependencies", "testCommand"],
};
```

## Run with the schema and read the parsed value

Detect an agent, create it, and pass the schema on the run. The parsed value is set on `result.json`, typed `unknown`, so cast it to the shape you asked for:

```ts
import { create, detect } from "anyagent";

const [found] = await detect();
if (!found) {
  throw new Error("No supported coding agent found.");
}

const agent = create(found);
const result = await agent.run(
  "Inspect this repo and report its runtime dependencies and the command " +
    "that runs its tests.",
  { schema }
);

const { dependencies, testCommand } = result.json as {
  dependencies: string[];
  testCommand: string;
};
console.log(testCommand, dependencies);
```

`result.json` holds the validated value:

```txt
bun test [ 'react', 'zod', 'hono' ]
```

The cast is yours to trust. AnyAgent validates the essential JSON Schema keywords and ignores the rest ([the reference lists which](/docs/api#baselinerunoptions)), and the TypeScript type is an assertion you write, so validate further yourself when a field carries meaning the schema cannot capture.

## Handle a reply that never matches

When the first reply fails to parse or validate, AnyAgent retries once. It re-asks the agent with the failed reply and the specific errors quoted, then validates the second reply. A successful retry returns normally, with the corrected value on `result.json`; the result’s `usage`, `events`, and `raw` then describe the retry run only, so the first attempt’s tokens are not in the totals.

<Callout type="warn">
  The retry is a second full agent run. On an agent that edits files, a run
  whose first reply fails validation acts on your repo twice. For extraction
  tasks, pair `schema` with a [read-only
  run](/docs/run-agents#keep-a-run-read-only) where the agent supports one, so
  a retry stays side-effect free.
</Callout>

When the retry also fails, `run()` throws `AnyAgentError` with `code: "Parse"`. The message carries the validation errors, and the agent’s final reply text is on `err.raw`. Each error carries a JSON path, so `$.user.name: expected string, got number` tells you which field came back wrong:

```ts
import { create, detect } from "anyagent";
import { AnyAgentError } from "anyagent/errors";

const [found] = await detect();
if (!found) {
  throw new Error("No supported coding agent found.");
}
const agent = create(found);

try {
  const result = await agent.run("Report this repo's dependencies.", {
    schema,
  });
  console.log(result.json);
} catch (err) {
  if (err instanceof AnyAgentError && err.code === "Parse") {
    console.error("The agent could not match the schema:", err.message);
    console.error("Its last reply was:", err.raw);
  } else {
    throw err;
  }
}
```

## Streaming a schema run

Iterating a schema run yields raw events as they arrive — including both attempts’ events when the automatic retry fires — and the terminal `done` carries the same parsed result awaiting resolves with. Parsing needs the whole reply, so `json` exists only on the final result, never mid-stream. See [Stream progress](/docs/streaming).

## Guard structured output on unknown agents

`capabilities.structuredOutput` guards the schema option. Every built-in adapter declares it, so a schema works on all of them; how each CLI produces the reply is on its [adapter page](/docs/adapters), and it never changes how you ask. When you drive a custom adapter that might not declare the capability, check first:

```ts
const opts = agent.capabilities.structuredOutput ? { schema } : {};
const result = await agent.run("Report this repo's dependencies.", opts);
```

Requesting a schema on an adapter that declares `structuredOutput: false` throws `AnyAgentError` with `code: "UnsupportedCapability"` before anything spawns. See [Handle errors](/docs/errors).
