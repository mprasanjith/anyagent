This page documents everything the `anyagent` package exports: the two entry-point functions, the types you pass and receive at runtime, the single error class, and the contract an adapter implements.

## Entry points

Import `detect`, `create`, `AnyAgentError`, and every type from the package root. Adapter authors also reach the `ndjsonParser` helper and the `Detection` type from the root, and the conformance suite from the `anyagent/conformance` subpath. Each built-in adapter has its own subpath, so importing one adapter never pulls in another and your tool ships only the adapters it uses.

```ts
import { AnyAgentError, create, detect, ndjsonParser } from "anyagent";
import type { Agent, Detection, RunOptions, RunResult } from "anyagent";
import { claudeCode } from "anyagent/claude-code";
import { codex } from "anyagent/codex";
import { opencode } from "anyagent/opencode";
import { kiloCode } from "anyagent/kilo-code";
import { pi } from "anyagent/pi";
import { goose } from "anyagent/goose";
import { cline } from "anyagent/cline";
import { runConformance } from "anyagent/conformance";
```

`claudeCode()`, `codex()`, `opencode()`, `kiloCode()`, `pi()`, `goose()`, and `cline()` are adapter factories: each returns an [`Adapter`](#adapter) you can hand to `create`. Their flag mappings and raw payload shapes live on the [adapter pages](/docs/adapters).

## detect

`detect` finds every supported coding agent installed on the machine and returns one [`DetectResult`](#detectresult) per installed agent. The list follows the adapter registry order, which carries no ranking, and is empty when nothing is installed.

```ts
const detect: (opts?: DetectOptions) => Promise<DetectResult[]>;
```

Call it with no arguments to scan the built-in adapters on the real machine, then pass the result you pick to `create`:

```ts
import { create, detect } from "anyagent";

const installed = await detect();
if (installed.length === 0) {
  throw new Error("No supported coding agent found.");
}
const agent = create(installed[0]);
```

`DetectOptions` overrides the defaults:

| Name       | Type           | Default                      | Description                                                                         |
| ---------- | -------------- | ---------------------------- | ----------------------------------------------------------------------------------- |
| `adapters` | `Adapter[]`    | the built-in adapters        | adapter list to scan; pass your own to scan a subset or include a custom adapter    |
| `probe`    | `VersionProbe` | a real `PATH` and exec probe | detection I/O; pass a fake so tests simulate any machine without spawning processes |

## create

`create` builds a runnable [`Agent`](#agent) from either an adapter or one of `detect`’s results. Use an adapter directly when you know which CLI you want; use a `DetectResult` when you want whatever is installed.

```ts
const create: (source: Adapter | DetectResult) => Agent;
```

The call is synchronous and spawns nothing; the process starts when you call `run` or `runStream`. It also never checks that the CLI is installed, so creating from an adapter on a machine without that CLI surfaces as an `Invocation` error on the first run.

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const result = await agent.run("Summarize this repo.");
console.log(result.text);
```

## Agent

An `Agent` is a ready-to-run handle on one installed CLI. `run` resolves with the final result; `runStream` yields events as the agent works and ends with a `done` event carrying that same result. Breaking out of the stream early kills the underlying process. Reach the native CLI through `raw`.

## RunOptions

Everything you can tune about a single run. All fields are optional. `permission`, `cwd`, `model`, `systemPrompt`, `resume`, `mcp`, and `schema` are validated against the agent’s [`CapabilityTable`](#capabilitytable) before any process spawns, so requesting something the CLI cannot do throws [`AnyAgentError`](#anyagenterror) with `code: "UnsupportedCapability"` up front. `env`, `signal`, and `extraArgs` work on every agent.

`schema` is a plain JSON Schema object. Pass it to [`run`](#agent) and the reply is parsed and validated against it, landing on [`RunResult.json`](#runresult); [Get structured output](/docs/structured-output) covers the parsing, validation, and retry path.

## PermissionLevel

`PermissionLevel` bounds how much autonomy the agent gets over your working directory. The enum has exactly three values and never widens. The default is `edit`. Each adapter maps your chosen level onto its CLI’s native flags; a CLI that cannot honor a level throws `UnsupportedCapability` rather than silently downgrading.

| Value            | Meaning                                                                                         |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| `read`           | inspect files and answer; change nothing                                                        |
| `edit` (default) | create and modify files, with the CLI’s own guardrails still gating actions like shell commands |
| `auto`           | auto-approve every permission prompt and run unattended                                         |

CLIs with finer-grained native levels expose them only through [`RunOptions.extraArgs`](#runoptions) or [`RawHandle`](#rawhandle).

## RunResult

What a finished run gives you back. Holding a `RunResult` means the run succeeded: the CLI exited cleanly and reported no agent-level error, since every failure path throws [`AnyAgentError`](#anyagenterror) instead. `text` is the final answer with all text output concatenated. `raw` is the CLI’s own final payload, untouched.

## AgentEvent

One normalized event from a running agent, as yielded by `runStream`. `AgentEvent` is a discriminated union on `type` with five variants. Every variant except `done` carries a `raw` field holding the CLI’s untouched native payload for that event.

| `type`        | Payload                           | Meaning                                    |
| ------------- | --------------------------------- | ------------------------------------------ |
| `text-delta`  | `text: string`                    | a piece of the agent’s answer text         |
| `tool-call`   | `name: string`, `input: unknown`  | the agent invoked a tool with this input   |
| `tool-result` | `name: string`, `output: unknown` | a tool returned this output                |
| `usage`       | `usage: Usage`                    | token and cost accounting became available |
| `done`        | `result: RunResult`               | the run finished; carries the final result |

How much text one `text-delta` carries depends on the agent: a token, a chunk, or a whole assistant message. The conformance suite guarantees that concatenating every delta’s `text` reproduces `RunResult.text` exactly.

## Usage

Token and cost accounting for a run, normalized across CLIs. Every field is optional because each CLI reports a different subset, so check for `undefined` rather than assuming a field is present. `inputTokens` counts uncached input only, matching the provider’s own accounting. For exact cache line items, read the native payload on the event’s or result’s `raw`.

## CapabilitySupport

How a capability is provided. Every [`CapabilityTable`](#capabilitytable) field except `permissionLevels` is a `CapabilitySupport`:

```ts
type CapabilitySupport = "native" | "emulated" | false;
```

| Value        | Meaning                                                                                               |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| `"native"`   | the CLI implements it, and the adapter maps your request onto the CLI’s own flags                     |
| `"emulated"` | the CLI has no such flag, so AnyAgent’s core provides the behavior itself, identically on every agent |
| `false`      | unavailable; requesting it throws `UnsupportedCapability` before anything spawns                      |

Both `"native"` and `"emulated"` are truthy, so a `caps.systemPrompt ? … : …` check still reads as “is this available”. [How AnyAgent works](/docs/how-it-works) explains the native-versus-emulated split.

## CapabilityTable

What one agent CLI can do. Read it from `agent.capabilities` or a [`DetectResult`](#detectresult) to find out what you can ask for before you ask. Every field except `permissionLevels` is a [`CapabilitySupport`](#capabilitysupport). Most fields guard the matching [`RunOptions`](#runoptions) field, so requesting an option the table declares as `false` throws `UnsupportedCapability`. `streaming` is the exception: it is informational, describing whether the agent emits progressive output rather than guarding an option.

## McpServer and McpConfig

`McpConfig` is the MCP (Model Context Protocol) servers for a run, keyed by the name the agent will see each server under. Each value is an `McpServer`. Set `command`, `args`, and optionally `env` for a local stdio server, or `url` for a remote one. The adapter translates this into whatever config format its CLI expects.

<auto-type-table
  path="../../../../packages/anyagent/src/types.ts"
  name="McpServer"
/>

`McpConfig` is the record type wrapping it:

```ts
type McpConfig = Record<string, McpServer>;
```

Pass it through [`RunOptions.mcp`](#runoptions) on an agent whose capability table declares `mcp: true`:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
await agent.run("List the tables the app touches.", {
  mcp: { db: { command: "npx", args: ["acme-db-mcp"] } },
});
```

## AgentId and KnownAgents

`AgentId` is the id of a coding agent, such as `"claude-code"`. The built-in ids autocomplete, but any string is accepted, so custom adapters fit too; an `AgentId` is still a `string` you can store or compare freely.

```ts
type AgentId = keyof KnownAgents | (string & Record<never, never>);
```

`KnownAgents` is the interface whose keys feed `AgentId`; it ships with a key for every built-in adapter (`"claude-code"`, `"codex"`, `"opencode"`, `"kilo-code"`, `"pi"`, `"goose"`, and `"cline"`). A third-party adapter teaches the type about its own id through module augmentation:

```ts
declare module "anyagent" {
  interface KnownAgents {
    "acme-cli": true;
  }
}
```

## AnyAgentError

The single error type everything in AnyAgent throws. There is no subclass tree; you branch on the `code` field. [Handle errors](/docs/errors) covers what to do about each code.

```ts
class AnyAgentError extends Error {
  readonly code: AnyAgentErrorCode;
  readonly raw?: unknown;
  readonly argv?: string[];
  readonly stderr?: string;
}
```

| Name     | Type                | Description                                                             |
| -------- | ------------------- | ----------------------------------------------------------------------- |
| `code`   | `AnyAgentErrorCode` | which way the run failed; one of the four values below                  |
| `raw`    | `unknown`           | the underlying cause: a native error or the CLI’s own error payload     |
| `argv`   | `string[]`          | the command line that ran; attached when a process was involved         |
| `stderr` | `string`            | what that process wrote to stderr; attached when a process was involved |

`AnyAgentErrorCode` is the union of the four codes:

```ts
type AnyAgentErrorCode =
  | "UnsupportedCapability"
  | "Invocation"
  | "Parse"
  | "Aborted";
```

| `code`                  | Cause                                                                                                                                               |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `UnsupportedCapability` | you asked for an option the capability table does not declare, or a permission level the CLI does not offer; thrown before anything spawns          |
| `Invocation`            | the CLI itself went wrong: it failed to spawn, exited nonzero, or reported an agent-level error; `argv` and `stderr` show what ran and what it said |
| `Parse`                 | the CLI ran, but its output did not match the shape the adapter expects, or the stream ended without a terminal `done` event                        |
| `Aborted`               | your `AbortSignal` fired and the run was terminated                                                                                                 |

Branch on `code` to handle a specific failure:

```ts
import { AnyAgentError, create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const controller = new AbortController();
const agent = create(claudeCode());

try {
  await agent.run("Summarize this repo.", { signal: controller.signal });
} catch (err) {
  if (err instanceof AnyAgentError && err.code === "Aborted") {
    console.log("Cancelled.");
  } else {
    throw err;
  }
}
```

The static `AnyAgentError.wrap(err, code?)` normalizes an unknown thrown value into an `AnyAgentError`. It returns the value unchanged if it is already an `AnyAgentError`, otherwise it builds a new one carrying the original as `raw`. The `code` argument defaults to `"Invocation"`. You need it when writing an adapter, not when handling errors.

```ts
const wrap: (err: unknown, code?: AnyAgentErrorCode) => AnyAgentError;
```

## Adapter contract

The types below are for adapter authors: they describe how a CLI is invoked and how its output is read. If you are building on top of AnyAgent rather than adding CLI support, you will not construct these directly. See [Adding an adapter](/docs/adding-an-adapter) for the full guide.

### Adapter

The contract for supporting one agent CLI. An adapter is data plus pure functions: it describes how to invoke its CLI and how to read its output, while the core does all I/O. `detect` is optional and replaces default detection entirely; most adapters omit it. `buildInvocation` is pure and must never launch a process. `parse` must end with exactly one `done` event and, under `strict`, throw `Parse` on any unrecognized shape.

### AdapterMeta

How an adapter identifies itself. `id` is the stable machine name such as `"claude-code"`, `name` the human-readable one, and `bin` the executable names to look for on `PATH` in priority order, where the first one found wins.

  name="AdapterMeta"
/>

### DetectionSpec

How detection reads a CLI’s version once its binary is found. An adapter sets these only when its CLI deviates from the defaults: `versionCommand` defaults to `["--version"]`, and `versionRegex` defaults to the first `x.y.z` triple in whatever the command prints.

<auto-type-table
  path="../../../../packages/anyagent/src/types.ts"
  name="DetectionSpec"
/>

### Invocation

A fully-resolved command line: what `buildInvocation` returns and what the core spawns. `env` is merged over the parent process’s environment rather than replacing it. `input`, when present, is written to the child’s stdin, which is then closed; this is how prompts reach CLIs that read them from a pipe.

<auto-type-table
  path="../../../../packages/anyagent/src/types.ts"
  name="Invocation"
/>

### OutputSource

The process output an adapter’s `parse` reads. Consume either `lines()` for NDJSON adapters or `text()` for plain-text adapters, never both, since the underlying stdout stream is read once. `stderr()` resolves complete only once `exitCode` has settled. The core calls `close()` when a consumer abandons a stream early.

<auto-type-table
  path="../../../../packages/anyagent/src/types.ts"
  name="OutputSource"
/>

### VersionProbe

The two I/O operations detection needs. `which` resolves a binary name to its path on `PATH`, or `null` when absent. `exec` runs a binary and captures its output. `detect` uses a real implementation by default; tests pass a fake via `detect({ probe })` to simulate any machine without spawning processes.

<auto-type-table
  path="../../../../packages/anyagent/src/types.ts"
  name="VersionProbe"
/>

### RawHandle

Direct access to the native CLI, reached through `agent.raw`, for capabilities the unified surface does not model. `buildInvocation` returns the exact command AnyAgent would run, useful for logging or running it elsewhere. `spawn` launches it and hands you the Node `ChildProcess` to drive yourself, with the prompt already wired to stdin and no normalized events or lifecycle management. See [Escape hatches](/docs/escape-hatches).
