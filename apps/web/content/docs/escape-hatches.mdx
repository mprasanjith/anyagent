---
title: Escape hatches
description: Reach native CLI capabilities the unified surface does not model, from adding one flag to owning the whole process.
---

The unified surface models what most agent CLIs share, so every CLI can do things it leaves out: bidirectional sessions, per-tool allow lists, harness-specific permission modes. AnyAgent gives you three ways down to a CLI’s native capabilities, in increasing order of control: `extraArgs`, `agent.raw.buildInvocation`, and `agent.raw.spawn`.

## Add native flags with extraArgs

`RunOptions.extraArgs` appends native CLI flags to the argv while everything else stays the same: you keep the normalized event stream and the lifecycle management. Reach for it when the surface almost fits and one flag closes the gap.

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const result = await agent.run("Generate API docs from the source.", {
  extraArgs: ["--permission-mode", "acceptEdits"],
});
```

Here a run pins Claude Code’s `acceptEdits` mode, one of the harness-specific middle grounds between `readOnly` and the unattended default that the surface deliberately does not model.

Two caveats apply: the flags are adapter-specific, so you own their correctness for the CLI you target, and they are appended after the flags AnyAgent builds, without validation, so a flag here can override what a typed option set; that is exactly what the example above relies on. Prefer a typed option whenever one exists; the [adapter pages](/docs/adapters) and the CLI’s own docs cover the rest.

## Get the exact command with agent.raw.buildInvocation

When you want the command without running it, `agent.raw.buildInvocation` returns the exact `Invocation` AnyAgent would spawn: `command`, `args`, `env`, `cwd`, and the `input` piped to stdin. Nothing spawns. Use it for logging, dry runs, or running the command somewhere else.

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const inv = agent.raw.buildInvocation("Audit the auth flow.", {
  readOnly: true,
});

console.log(inv.command, inv.args.join(" "));
// claude -p --output-format stream-json --verbose --permission-mode manual
//   --disallowedTools Bash,Edit,NotebookEdit,Write
```

Unlike `run` and `runStream`, both `raw` calls skip capability validation and [emulation](/docs/how-it-works): an option the CLI does not support is silently left out of the argv rather than throwing `UnsupportedCapability`, and an emulated option such as a system prompt on a CLI without the flag is not folded into the prompt for you. Check `agent.capabilities` yourself when it matters.

## Own the process with agent.raw.spawn

When you need to drive the CLI yourself, `agent.raw.spawn` launches the invocation and returns the Node `ChildProcess`, with the prompt already written to stdin. This is the most control and the most work: you read stdout, you handle exit, and you get no normalized events and no lifecycle management. Of the run options, `signal` still applies; aborting it terminates the process.

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const child = agent.raw.spawn("Explain the auth flow.", { readOnly: true });

child.stdout?.pipe(process.stdout);
child.on("exit", (code) => console.log(`agent exited with ${code}`));
```

Reach for this when you need bidirectional interaction or custom parsing the normalized stream cannot give you.

## Pick the smallest hatch

Pick the smallest hatch that solves your problem:

| You need                                             | Reach for                   |
| ---------------------------------------------------- | --------------------------- |
| One native flag the surface does not model           | `extraArgs`                 |
| The exact argv, for logging or running it elsewhere  | `agent.raw.buildInvocation` |
| To own the process: custom parsing, bidirectional IO | `agent.raw.spawn`           |

Before you rebuild event parsing on top of `spawn` for a supported CLI, check the normalized stream first. Every event’s `raw` field carries the untouched native payload, so what you are after may already be there without leaving the surface.
