---
title: Use Agent Skills with any agent
description: Let the CLI pick up an Agent Skill from the repo, stage one for a single run, and fall back to the system prompt where skills are unsupported.
---

[Agent Skills](https://agentskills.io) are folders holding a `SKILL.md` file that a coding agent loads when a task calls for it. The CLIs discover them from the filesystem themselves, so AnyAgent adds no API for skills: place a skill in the repo the agent works on and set [`cwd`](/docs/run-agents#tune-the-run), and the CLI finds it. This page shows the discovery paths, how to stage a skill for one run, and what to do on an agent that has no skills support.

## Where each agent looks for skills

Each CLI reads skills from its own directories, at a project level (relative to `cwd`) and a user level (under the home directory). These are verified against each CLI’s current documentation:

| Agent       | Project paths                                                            | User paths                                 |
| ----------- | ------------------------------------------------------------------------ | ------------------------------------------ |
| Claude Code | `.claude/skills/`                                                        | `~/.claude/skills/`                        |
| Codex       | `.agents/skills/`                                                        | `~/.agents/skills/`                        |
| opencode    | `.opencode/skills/`, `.claude/skills/`, `.agents/skills/`                | user-level equivalents of each             |
| Pi          | `.pi/skills/`, `.agents/skills/`                                         | `~/.pi/agent/skills/`, `~/.agents/skills/` |
| goose       | `.agents/skills/`                                                        | `~/.agents/skills/`                        |
| Gemini CLI  | `.agents/skills/`, `.gemini/skills/`                                     | `~/.agents/skills/`, `~/.gemini/skills/`   |
| Antigravity | `.agents/skills/`                                                        | `~/.gemini/config/skills/`                 |
| Cursor      | `.agents/skills/`, `.cursor/skills/`, `.claude/skills/`, `.codex/skills/` | user-level equivalents of each             |
| Kilo Code   | none                                                                     | none                                       |
| Cline       | none                                                                     | none                                       |

`.agents/skills/` is the shared path: every skills-capable agent except Claude Code reads it, so a skill placed there reaches all of them at once. Claude Code reads `.claude/skills/` instead (Cursor and opencode read that path too). Pi also accepts a repeatable `--skill <path>` flag, which you can pass through [`extraArgs`](/docs/escape-hatches). Kilo Code and Cline have no skills support today.

## Let an installed skill get picked up

When the skill already lives in the target repo, there is nothing to wire. Point the run at that repo with `cwd`, and the CLI discovers the skill under its own directory:

```ts
import { create, detect } from "anyagent";

const [found] = await detect();
if (!found) {
  throw new Error("No supported coding agent found.");
}

const agent = create(found);
await agent.run("Set up the Acme SDK using the acme-setup skill.", {
  cwd: "/home/sam/projects/acme-app",
});
```

## Stage a skill for one run

When you ship the skill with your tool rather than expecting it in the repo, copy it into the detected agent’s discovery path before the run and remove it after. Key the path off the detected agent’s id: `.claude/skills` for Claude Code, `.agents/skills` for the others.

```ts
import { create, detect } from "anyagent";
import { existsSync } from "node:fs";
import { appendFile, cp, mkdir, rm } from "node:fs/promises";
import { join } from "node:path";

const repo = "/home/sam/projects/acme-app";
const [found] = await detect();
if (!found) {
  throw new Error("No supported coding agent found.");
}
const agent = create(found);

const skillsDir =
  found.id === "claude-code" ? ".claude/skills" : ".agents/skills";
const target = join(repo, skillsDir, "acme-setup");

// Only touch a path you own: refuse to overwrite an existing directory.
if (existsSync(target)) {
  throw new Error(`${target} already exists; leaving it untouched.`);
}
await mkdir(target, { recursive: true });
await cp("./skills/acme-setup", target, { recursive: true });
// Keep staged files out of the diff so the unattended run cannot commit them.
await appendFile(join(repo, ".git/info/exclude"), `\n${skillsDir}/\n`);

try {
  const result = await agent.run(
    "Set up the Acme SDK using the acme-setup skill.",
    { cwd: repo }
  );
  console.log(result.text);
} finally {
  await rm(target, { recursive: true, force: true });
}
```

Two hygiene rules keep this safe. Create then delete only the directory you staged, and bail when it already exists, so you never remove a skill the user installed. Add the staged path to `.git/info/exclude`, so the unattended run cannot commit your temporary files into the user’s history. The `finally` removes the skill whether the run succeeds or throws.

## Fall back to the system prompt when skills are unsupported

Kilo Code and Cline discover no skills, so on those agents fold the instructions into the run instead. `systemPrompt` reaches every built-in agent, natively on some and provided by AnyAgent on the rest ([the matrix](/docs/adapters) shows which), so the same call works everywhere:

```ts
import { readFile } from "node:fs/promises";

const instructions = await readFile("./skills/acme-setup/SKILL.md", "utf8");
await agent.run("Set up the Acme SDK.", {
  cwd: "/home/sam/projects/acme-app",
  systemPrompt: instructions,
});
```

Branch on `found.id` to stage a skill when the agent supports one and fall back to `systemPrompt` when it does not, so your tool drives every agent from a single skill source.
