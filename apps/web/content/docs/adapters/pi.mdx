title: Pi
description: How the pi adapter detects and invokes the Pi CLI’s pi binary, and what each run option maps to.

The `pi` adapter drives the Pi CLI as `pi --mode json -p`, mapping Pi’s session, turn, and message NDJSON stream onto AnyAgent’s normalized events. Pi streams token-level deltas, so `text-delta` events are fine-grained rather than whole messages, and Pi extends through its own extension system rather than MCP, so the `mcp` option is unsupported. Pi is MIT-licensed and pure bring-your-own-key (BYOK): it reads provider keys from around 20 env vars (`OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, …), so it needs no subscription or account. The full capability table is on the [support matrix](/docs/adapters).

Import the factory from the `anyagent/pi` subpath and hand it to `create`:

```ts
import { create } from "anyagent";
import { pi } from "anyagent/pi";

const agent = create(pi());
const result = await agent.run("summarize this repo", {
  model: "openrouter/openai/gpt-5.2",
});
```

Detection looks for a `pi` binary on `PATH` and reads the version from `pi --version`.

## How options map to flags

Every run executes `pi --mode json -p`. Pi takes the prompt as a positional argument and has no stdin form, so a prompt larger than the OS argv limit needs [`agent.raw`](/docs/escape-hatches). Your [run options](/docs/api#runoptions) append further flags:

| Option               | Flag                            |
| -------------------- | ------------------------------- |
| `permission: "read"` | `--tools read`                  |
| `permission: "edit"` | none, the default toolset       |
| `permission: "auto"` | none, same as `edit`            |
| `model`              | `--model <pattern>`             |
| `systemPrompt`       | `--append-system-prompt <text>` |
| `resume`             | `--session-id <id>`             |

Pi has no approval prompts at all and always runs autonomously, so `edit` and `auto` are the same thing. `read` restricts the toolset to the `read` tool rather than sandboxing.

`cwd` and `env` are not flags: they become the spawned process’s working directory and extra environment variables. [`extraArgs`](/docs/escape-hatches) appends after every flag above, so a native flag there can override what `permission` set.

## What the stream produces

`text-delta` events carry individual tokens from Pi’s message-update events. Tool calls surface when their arguments are complete, and each tool result arrives as its own message carrying the tool’s name.

Pi has no single final payload, so the adapter composes one carrying the session id: read `sessionId` from `result.raw` and pass it back as `resume`; see [Resume a session](/docs/run-agents#resume-a-session).

## Usage reporting

Pi reports `inputTokens`, `outputTokens`, and `costUsd` per turn: each `turn_end` yields a `usage` event carrying that turn’s share, and `result.usage` carries the totals summed across the run.

## Errors

Pi exits 0 even when a turn fails, so the adapter never trusts the exit code: a turn ending with `stopReason: "error"`, or a top-level `error` event, throws [`AnyAgentError`](/docs/errors) with `code: "Invocation"` and Pi’s own message.
