The `antigravity` adapter drives the Antigravity CLI in its headless print mode, detected as the `agy` binary on `PATH`; import `antigravity` from `anyagent/antigravity`. Model listing, model selection, effort, and session resume are native; `readOnly` and `mcp` are undeclared, and requesting them throws; system prompts and structured output are emulated. The full grid is on the [support matrix](/docs/adapters).

## How options map to flags

Every run executes `agy -p <prompt> --output-format stream-json --dangerously-skip-permissions`, with the prompt as `-p`'s value — piped stdin is ignored in print mode, so the prompt always rides argv. [Run options](/docs/api#run-options) append flags:

| Option   | Flag                                                            |
| -------- | ----------------------------------------------------------------- |
| `model`  | `--model <id>`, ids verbatim from `models()`                    |
| `effort` | `--effort <level>`, closed vocabulary: `low`, `medium`, `high`  |
| `resume` | `--conversation <sessionId>`                                    |

## Quirks

- The exit code lies: a self-canceled headless run reports `status: "CANCELED"` with exit 0, so the adapter trusts only the `result` status and throws `Invocation` on anything but `SUCCESS`.
- No read-only run exists: `--mode plan` refuses workspace writes but leaves Antigravity's always-allowed internal scratch directories writable (verified: a plan-mode run created a real file there and reported success), so `readOnly: true` throws; plan mode stays reachable via `extraArgs: ["--mode", "plan"]`.
- Permissions are skipped on purpose: without the flag, headless permission asks are auto-denied — a denied tool surfaces as an `ERROR`-state step and an advisory `tool-result` while the run still ends `SUCCESS`.
- `models()` runs `agy models`, a plain one-id-per-line, cross-vendor catalog (gemini, claude, and gpt-oss families); many ids also bake an effort level into the name.
- `authStatus()` is probed: the CLI has no status subcommand and no readable credential file, so a model listing means authenticated and a sign-in notice means not.
- Print mode times out after 5 minutes by default; give a longer run `extraArgs: ["--print-timeout", "30m"]`.
- The default model (`auto`) can spiral on trivial prompts; pin `model` for predictable cost.
- The init event's conversation id lands on `result.sessionId` and resumes via `resume`.
- `usage` maps the CLI's `thinking_tokens` to `reasoningTokens`; no cache line items are reported.
