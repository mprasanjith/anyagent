title: Claude Code

The `claude-code` adapter drives Anthropic's Claude Code CLI in headless mode. It declares the full capability table, and it is the reference implementation to mirror when you are [adding an adapter](/docs/adding-an-adapter). This page covers detection, the capability table, how each run option maps to a CLI flag, what the stream produces, how usage is reported, and how to resume a session.

Import the factory from the `anyagent/claude-code` subpath and hand it to `create`:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const result = await agent.run("summarize this repo");
```

## Detection

Detection looks for a `claude` binary on `PATH` and reads the version from `claude --version`. The version lands on [`DetectResult.version`](/docs/api#detectresult) for display only; AnyAgent never changes behavior based on it, and a failed version probe leaves it `null` without blocking use.

## Capabilities

The adapter declares every field of the [capability table](/docs/api#capabilitytable) as supported:

| Capability         | Value                                           |
| ------------------ | ----------------------------------------------- |
| `streaming`        | `true`, a live NDJSON stream                    |
| `permissionLevels` | `read`, `edit`, `auto`                          |
| `modelSelection`   | `true`                                          |
| `sessionResume`    | `true`                                          |
| `mcp`              | `true`                                          |
| `systemPrompt`     | `true`                                          |
| `cwd`              | `true`                                          |
| `structuredOutput` | `true`, informational; reach it via `extraArgs` |

## How options map to flags

Every run executes `claude -p --output-format stream-json --verbose` with a `--permission-mode` flag set from the permission level. The prompt travels over stdin rather than as a positional argument, so a large prompt never hits the OS argv size limit. Your [run options](/docs/api#runoptions) append further flags:

| Option               | Flag                                                               |
| -------------------- | ------------------------------------------------------------------ |
| `permission: "read"` | `--permission-mode default`                                        |
| `permission: "edit"` | `--permission-mode acceptEdits`                                    |
| `permission: "auto"` | `--permission-mode bypassPermissions`                              |
| `model`              | `--model <name>`, in Claude Code's own vocabulary such as `"opus"` |
| `systemPrompt`       | `--append-system-prompt <text>`, which appends and never replaces  |
| `resume`             | `--resume <sessionId>`                                             |
| `mcp`                | `--mcp-config <json>`, the servers serialized to JSON              |

## What the stream produces

Claude Code emits whole assistant messages, so one `text-delta` carries a full message rather than a token. Thinking blocks produce no normalized event, though the reasoning stays reachable on the surrounding raw payloads.

Tool use maps to `tool-call` and its result to `tool-result`. Concatenating every `text-delta` reproduces `RunResult.text` exactly, as the conformance suite requires.

## Usage reporting

Usage lands on [`RunResult.usage`](/docs/api#usage) with `inputTokens`, `outputTokens`, and `costUsd`. `inputTokens` counts uncached input only. Cache reads and writes stay as separate line items on `result.raw`, so read the raw payload when you need exact cache accounting.

## Errors

When the CLI reports an agent-level error, the run throws [`AnyAgentError`](/docs/errors) with `code: "Invocation"` and the CLI's own error detail. A nonzero exit or a spawn failure throws the same code.

## Resume a session

Claude Code reports a session id in its final payload. Read `session_id` from `result.raw` and pass it back as `resume`:

```ts
const first = await agent.run("review the auth module");
const { session_id } = first.raw as { session_id?: string };

const followUp = await agent.run("now fix what you found", {
  resume: session_id,
});
```
