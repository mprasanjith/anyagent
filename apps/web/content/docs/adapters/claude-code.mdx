The `claude-code` adapter drives the Claude Code CLI in headless mode, detected as the `claude` binary on `PATH`. It supports streaming, all three permission levels, model selection, session resume, MCP servers, system prompts, and `cwd`. The full capability table is on the [support matrix](/docs/adapters).

Import the factory from the `anyagent/claude-code` subpath and hand it to `create`:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const result = await agent.run("summarize this repo");
```

One capability is emulated rather than native: Claude Code has its own schema flag for structured output, but it is not yet verified against recorded output, so the core appends your schema to the prompt and parses the reply. See [Get structured output](/docs/structured-output).

## How options map to flags

Every run executes `claude -p --output-format stream-json --verbose` with a `--permission-mode` flag set from the permission level. The prompt travels over stdin rather than as a positional argument, so a large prompt never exceeds the OS argv size limit. Your [run options](/docs/api#runoptions) append further flags:

| Option               | Flag                                                               |
| -------------------- | ------------------------------------------------------------------ |
| `permission: "read"` | `--permission-mode default`                                        |
| `permission: "edit"` | `--permission-mode acceptEdits`                                    |
| `permission: "auto"` | `--permission-mode bypassPermissions`                              |
| `model`              | `--model <name>`, in Claude Code’s own vocabulary such as `"opus"` |
| `systemPrompt`       | `--append-system-prompt <text>`, which appends and never replaces  |
| `resume`             | `--resume <sessionId>`                                             |
| `mcp`                | `--mcp-config <json>`, the servers under an `mcpServers` key       |

`cwd` and `env` are not flags: they become the spawned process’s working directory and extra environment variables. [`extraArgs`](/docs/escape-hatches) appends after every flag above, so a native flag there can override what `permission` set.

## What the stream produces

Claude Code emits whole assistant messages, so one `text-delta` carries a message’s full text block rather than a token. Tool use maps to `tool-call`, and its result to `tool-result`.

Thinking blocks produce no normalized event, and each event’s `raw` holds only its own content block, so reasoning appears nowhere on the normalized stream. To capture it, drive the CLI through [`agent.raw`](/docs/escape-hatches).

Claude Code reports a session id in its final payload: read `session_id` from `result.raw` and pass it back as `resume`; see [Resume a session](/docs/run-agents#resume-a-session).

## Usage reporting

Claude Code reports cost, so `costUsd` is set alongside the token counts. `inputTokens` counts uncached input only; cache reads and writes stay as separate line items on `result.raw`, so read the raw payload when you need exact cache accounting.
