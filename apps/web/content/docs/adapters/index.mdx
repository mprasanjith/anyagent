These are the agent CLIs AnyAgent supports. `detect()` scans for all of them in the order below, and each has its own subpath export for targeting it directly. The table is rendered from each adapter’s own capability declaration, so it always matches what the code enforces.

<CapabilityMatrix />

A `native` capability maps onto the CLI’s own flag; an `emulated` one is provided by AnyAgent’s core, identically on every agent that declares it; `—` means requesting it throws `UnsupportedCapability` before anything spawns. [How AnyAgent works](/docs/how-it-works) explains the split. Structured output reads `emulated` everywhere because the core appends your schema to the prompt and parses the reply itself on every CLI.

Everything else CLI-specific lives on the adapter’s page: the native flag behind each run option, what its stream produces, where its session id lives on `raw`, and its quirks. The pages share one section order, so a fact about one agent sits in the same place on every other. An adapter ships only against recorded real CLI output, never a guessed schema.
