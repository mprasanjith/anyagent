The `codex` adapter drives the Codex CLI, detected as the `codex` binary on `PATH`, through its non-interactive `codex exec --json` mode; import `codex` from `anyagent/codex`. Auth status and model listing are native; system prompts and structured output are emulated; `mcp` is undeclared, reachable through Codex’s `-c` config overrides via [`extraArgs`](/docs/escape-hatches). The full grid is on the [support matrix](/docs/adapters).

## How options map to flags

Every run executes `codex exec --json --sandbox danger-full-access`, the unattended default, with the prompt piped over stdin through the `-` positional. [Run options](/docs/api#run-options) change the sandbox and append flags:

| Option           | Flag                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| `readOnly: true` | `--sandbox read-only`                                                          |
| `model`          | `--model <name>`                                                               |
| `effort`         | `-c model_reasoning_effort="<value>"`, passed through verbatim                 |
| `resume`         | `codex exec resume <threadId>`, with the sandbox set via `-c sandbox_mode="…"` |

## Quirks

- The sandbox is always passed explicitly: `codex exec` defaults to read-only, which would silently under-honor AnyAgent’s full-autonomy default.
- `effort` has no closed vocabulary; accepted values are per-model, listed by `models()` on [`ModelInfo.reasoningEfforts`](/docs/api#modelinfo).
- `authStatus()` asks `codex login status`; `models()` asks `codex debug models`.
- Structured output is emulated on purpose: Codex’s `--output-schema` accepts a restricted schema dialect (every field required, `format` and `pattern` ignored), so native acceptance would depend on your schema.
- A `systemPrompt` is emulated: `codex exec` has no append-system-prompt flag.
- Command executions surface as `bash` tool events (native name `command_execution`), file changes as a pair named `file_change`; reasoning items produce no events.
- The `thread.started` id lands on `result.sessionId`; pass it back as `resume`.
- Codex folds cache reads into `input_tokens` and reasoning into `output_tokens`, and `Usage` keeps that accounting: `cacheReadTokens` and `reasoningTokens` are the folded shares, not additions. No cost is reported.
