The `codex` adapter drives OpenAI’s Codex CLI through `codex exec --json`, mapping its thread, turn, and item events onto AnyAgent’s normalized stream.

Import the factory from the `anyagent/codex` subpath and hand it to `create`:

```ts
import { create } from "anyagent";
import { codex } from "anyagent/codex";

const agent = create(codex());
const result = await agent.run("summarize this repo");
```

## Detection

Detection looks for a `codex` binary on `PATH` and reads the version from `codex --version`. The version lands on [`DetectResult.version`](/docs/api#detectresult) for display only; behavior never depends on it.

## Capabilities

The adapter declares one option as unsupported, `mcp`, and provides `systemPrompt` and `structuredOutput` through core [emulation](/docs/api#capabilitysupport):

| Capability         | Value                          |
| ------------------ | ------------------------------ |
| `streaming`        | `native`, a live NDJSON stream |
| `permissionLevels` | `read`, `edit`, `auto`         |
| `modelSelection`   | `native`                       |
| `sessionResume`    | `native`                       |
| `mcp`              | `false`                        |
| `systemPrompt`     | `emulated`                     |
| `structuredOutput` | `emulated`                     |
| `cwd`              | `native`                       |

`codex exec` has no append-system-prompt flag, so a `systemPrompt` is `emulated`: the core folds it into the prompt text ahead of your prompt, and you set it the same way as on any other agent.

```txt
<system-instructions>
{your system prompt}
</system-instructions>

{your prompt}
```

Structured output is `emulated` too: Codex has a native `--output-schema` path, but until it is verified against recorded output the core appends your schema to the prompt and parses the reply. See [Get structured output](/docs/structured-output).

Requesting `mcp` throws [`AnyAgentError`](/docs/errors) with `code: "UnsupportedCapability"` before anything spawns. Codex can reach MCP through its own `-c` config overrides, available via [`extraArgs` or `agent.raw`](/docs/escape-hatches).

## How options map to flags

Every run executes `codex exec --json` with the prompt piped over stdin through the `-` positional, so a large prompt never hits the OS argv size limit. Your [run options](/docs/api#runoptions) set the sandbox and append further flags:

| Option               | Flag                                                                           |
| -------------------- | ------------------------------------------------------------------------------ |
| `permission: "read"` | `--sandbox read-only`                                                          |
| `permission: "edit"` | `--sandbox workspace-write`                                                    |
| `permission: "auto"` | `--sandbox danger-full-access`                                                 |
| `model`              | `--model <name>`                                                               |
| `resume`             | `codex exec resume <threadId>`, with the sandbox set via `-c sandbox_mode="…"` |

The sandbox level is always passed explicitly. `codex exec` defaults to a read-only sandbox, which would weaken AnyAgent’s `edit` default if the flag were omitted. On resume, `codex exec resume` has no `--sandbox` flag, so the adapter sets the sandbox through a `-c sandbox_mode` config override instead.

`cwd` and `env` are not flags: they become the spawned process’s working directory and extra environment variables. [`extraArgs`](/docs/escape-hatches) appends after every flag above, so a native flag there can override what `permission` set.

## What the stream produces

Text arrives when a message completes, so the answer is never double-counted against its in-progress updates. Command executions and file changes map to `tool-call` and `tool-result` events.

Reasoning items and advisory error items produce no normalized event; a fatal failure throws instead of streaming. To capture reasoning, drive the CLI through [`agent.raw`](/docs/escape-hatches).

## Usage reporting

Usage lands on [`RunResult.usage`](/docs/api#usage) with `inputTokens` and `outputTokens`. Codex folds cache reads into its native `input_tokens`, so the adapter subtracts `cached_input_tokens` to report uncached input like the other adapters, and the exact native accounting stays on `raw`. Codex reports no cost, so `costUsd` is `undefined`.

## Errors

A top-level `error` event or a failed turn throws [`AnyAgentError`](/docs/errors) with `code: "Invocation"` and Codex’s own message. A nonzero exit or a spawn failure throws the same code.

## Resume a session

Codex has no single final payload, so the adapter composes one. `result.raw` carries the thread id alongside the native turn-completed event. Read `threadId` and pass it back as `resume`:

```ts
const first = await agent.run("start reviewing this repo");
const { threadId } = first.raw as { threadId?: string };

const followUp = await agent.run("continue with src/", { resume: threadId });
```
