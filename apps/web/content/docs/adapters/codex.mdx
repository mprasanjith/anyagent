---
title: Codex
description: How the codex adapter detects, invokes, and parses OpenAI's Codex CLI.
---

The `codex` adapter drives OpenAI's Codex CLI through `codex exec --json`, mapping its thread, turn, and item events onto anyagent's normalized stream.

```ts
import { create } from "anyagent";
import { codex } from "anyagent/codex";

const agent = create(codex());
const result = await agent.run("Summarize this repo.");
```

## Detection

Detection looks for a `codex` binary on `PATH` and reads its version from `codex --version`. The version is display-only, and behavior never depends on it.

## Capabilities

| Capability         | Value                                            |
| ------------------ | ------------------------------------------------ |
| `streaming`        | `true` (live NDJSON stream)                      |
| `permissionLevels` | `read-only`, `edit`, `full-auto`                 |
| `modelSelection`   | `true`                                           |
| `sessionResume`    | `true`                                           |
| `mcp`              | `false`                                          |
| `systemPrompt`     | `false`                                          |
| `cwd`              | `true`                                           |
| `structuredOutput` | `true` (informational, reach it via `extraArgs`) |

Requesting `mcp` or `systemPrompt` on this adapter throws `AnyAgentError` with `code: "UnsupportedCapability"`. Codex can reach both through its `-c` config overrides, which you can pass via [`extraArgs` or `agent.raw`](/docs/escape-hatches).

## How options map to flags

Every run executes `codex exec --json`, with the prompt piped over stdin (the `-` positional) so a large prompt never hits the OS argv size limit. Your options append flags:

| Option                    | Flag                                                                        |
| ------------------------- | --------------------------------------------------------------------------- |
| `permission: "read-only"` | `--sandbox read-only`                                                       |
| `permission: "edit"`      | `--sandbox workspace-write`                                                 |
| `permission: "full-auto"` | `--sandbox danger-full-access`                                              |
| `model`                   | `--model <name>`                                                            |
| `resume`                  | `codex exec resume <threadId>` with the sandbox set via `-c sandbox_mode=…` |

The sandbox level is always passed explicitly. `codex exec` defaults to a read-only sandbox, which would quietly weaken anyagent's `edit` default if the flag were omitted.

## What to expect from the stream

Text arrives when a message completes, so the answer is never double-counted against its in-progress updates. Command executions and file changes map to `tool-call` and `tool-result` events, and reasoning items produce no normalized event.

Usage has one quirk worth knowing: Codex folds cache reads into its `input_tokens`, so the adapter subtracts `cached_input_tokens` to report uncached input like the other adapters. The exact native accounting stays on `raw`. Codex reports no cost, so `costUsd` is `undefined`.

A top-level `error` or a failed turn throws `AnyAgentError` with `code: "Invocation"`.

## Resume a session

Codex has no single final payload, so the adapter composes one. `result.raw` carries the thread id alongside the native turn-completed event:

```ts
const first = await agent.run("Start reviewing this repo.");
const { threadId } = first.raw as { threadId?: string };

const followUp = await agent.run("Continue with src/.", { resume: threadId });
```
