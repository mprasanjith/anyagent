title: Gemini CLI

The `gemini-cli` adapter drives the Gemini CLI in headless mode, detected as the `gemini` binary on `PATH`; import `geminiCli` from `anyagent/gemini-cli`. Model selection, read-only runs, and session resume are native; system prompt and structured output are emulated; auth status is probed from local credentials. The full grid is on the [support matrix](/docs/adapters).

## How options map to flags

Every run executes `gemini -p "" --output-format stream-json --skip-trust --approval-mode yolo`, the unattended default, with the prompt piped over stdin. [Run options](/docs/api#run-options) change the mode and append flags:

| Option           | Flag                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| `readOnly: true` | `--approval-mode default`, whose headless toolset has no write or shell tools |
| `model`          | `-m <name>`, in the Gemini CLI's own vocabulary; never defaulted        |
| `resume`         | `--resume <sessionId>`, the UUID from `RunResult.sessionId`             |
| `systemPrompt`   | emulated: folded into the prompt as a preamble                          |
| `schema`         | emulated: schema instructions travel in the prompt                      |

## Quirks

- `--skip-trust` is always passed: an untrusted working directory otherwise exits 55 before doing anything.
- `readOnly` deliberately avoids `--approval-mode plan`: headless, the model can call `exit_plan_mode`, which self-approves, and then write freely. In `default` mode the mutating tools are never registered, so a write is structurally impossible.
- Never leave the model unset expecting a sane default: the CLI's automatic routing can spend minutes self-investigating a trivial prompt. Pin a model.
- Model aliases are rerouted upstream: requesting `gemini-2.5-flash` runs and reports `gemini-3.5-flash` in the stats.
- Assistant text arrives as genuine deltas; the stream carries no thinking output.
- The prompt is echoed back as a `user` message and dropped; the `init` event's session id lands on `result.sessionId`.
- Usage maps the terminal stats block: `cached` becomes `cacheReadTokens`, and the per-model breakdown stays on the usage event's `raw`.
- A `result` with `status: "error"` throws `AnyAgentError` with the agent's own message, ahead of the CLI's nonzero exit.
- `authStatus()` is a heuristic over `~/.gemini/oauth_creds.json`, `GEMINI_API_KEY`/`GOOGLE_API_KEY`, and `~/.gemini/settings.json`; a selected auth type with no visible key answers `"unknown"`, since keys can live in the OS keychain.
