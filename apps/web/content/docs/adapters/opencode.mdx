---
title: opencode
description: How the opencode adapter detects, invokes, and parses the opencode CLI, and what each run option maps to.
---

The `opencode` adapter drives the opencode CLI, detected as the `opencode` binary on `PATH`, through `opencode run --format json`, mapping opencode’s step, text, and tool event stream onto AnyAgent’s normalized events. opencode is bring-your-own-key (BYOK): it reads standard provider keys (`OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, …) from the environment, so it needs no subscription or account. The full capability table is on the [support matrix](/docs/adapters).

Import the factory from the `anyagent/opencode` subpath and hand it to `create`:

```ts
import { create } from "anyagent";
import { opencode } from "anyagent/opencode";

const agent = create(opencode());
const result = await agent.run("summarize this repo", {
  model: "openrouter/openai/gpt-5.2",
});
```

There is no `read` permission level. opencode’s per-tool permissions live in `opencode.json` (or the `OPENCODE_PERMISSION` env var) rather than flags, and a config-denied action in a non-interactive run can hang waiting for an approval that never comes, so the adapter refuses to fake a sandbox it cannot guarantee. MCP servers are also a config-file concern; reach them through opencode’s own config or [`extraArgs`](/docs/escape-hatches).

opencode has no per-run append-system-prompt flag, so a `systemPrompt` is emulated: the core folds it into the prompt text ahead of your prompt, and you set it the same way as on any other agent. Structured output is emulated too: the core appends your schema to the prompt and parses the reply. See [Get structured output](/docs/structured-output).

## How options map to flags

Every run executes `opencode run --format json` with the prompt piped over stdin, so a large prompt never exceeds the OS argv size limit. Your [run options](/docs/api#runoptions) append further flags:

| Option               | Flag                                |
| -------------------- | ----------------------------------- |
| `permission: "edit"` | none, opencode’s own defaults apply |
| `permission: "auto"` | `--auto`                            |
| `model`              | `--model <provider/model>`          |
| `resume`             | `--session <sessionId>`             |

`edit` is opencode’s default behavior: the CLI creates and modifies files, with whatever permission config the user has set still applying. `auto` adds `--auto`, which approves everything not explicitly denied.

`cwd` and `env` are not flags: they become the spawned process’s working directory and extra environment variables. [`extraArgs`](/docs/escape-hatches) appends after every flag above, so a native flag there can override what `permission` set.

## What the stream produces

Text arrives when a message part completes, so the answer is never double-counted against its in-progress updates. Tool parts arrive in a terminal state, input and output together, so one raw `tool_use` event produces both the `tool-call` and its `tool-result`.

opencode has no single final payload, so the adapter composes one carrying the session id. Read `sessionId` from `result.raw` and pass it back as `resume`; see [Resume a session](/docs/run-agents#resume-a-session).

## Usage reporting

opencode reports tokens and cost per step, so each `step_finish` yields a `usage` event carrying that step’s share, and `result.usage` carries the totals summed across the run.
