---
title: opencode
description: How the opencode adapter invokes and parses the opencode CLI, and what its BYOK setup needs.
---

The `opencode` adapter drives `opencode run --format json` with the prompt piped over stdin, mapping the step/text/tool event stream onto AnyAgent's normalized events. opencode is BYOK: it auto-detects standard provider keys (`OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, …) from the environment, so no subscription or account is required.

Import the factory from the `anyagent/opencode` subpath and hand it to `create`:

```ts
import { create } from "anyagent";
import { opencode } from "anyagent/opencode";

const agent = create(opencode());
const result = await agent.run("summarize this repo", {
  model: "openrouter/openai/gpt-4o-mini",
});
```

## Detection

Detection looks for an `opencode` binary on `PATH` and reads the version from `opencode --version`.

## Capabilities

| Capability         | Value                        |
| ------------------ | ---------------------------- |
| `streaming`        | `true`, a live NDJSON stream |
| `permissionLevels` | `edit`, `auto`               |
| `modelSelection`   | `true`, as `provider/model`  |
| `sessionResume`    | `true`                       |
| `mcp`              | `false`                      |
| `systemPrompt`     | `false`                      |
| `cwd`              | `true`                       |
| `structuredOutput` | `false`                      |

There is no `read` level. opencode's per-tool permissions live in `opencode.json` (or the `OPENCODE_PERMISSION` env var), not flags — and a config-denied action in a non-interactive run can hang waiting for an approval that never comes, so the adapter refuses to fake a sandbox it cannot guarantee. MCP servers and system prompts are also config-file concerns; reach them via opencode's own config or [`extraArgs`](/docs/escape-hatches).

## How options map to flags

| Option               | Flag                                 |
| -------------------- | ------------------------------------ |
| `permission: "edit"` | none — opencode's own defaults apply |
| `permission: "auto"` | `--auto`                             |
| `model`              | `--model <provider/model>`           |
| `resume`             | `--session <sessionId>`              |

`edit` is opencode's default behavior: the CLI creates and modifies files, with whatever permission config the user has set still applying. `auto` adds `--auto`, which approves everything not explicitly denied.

## What the stream produces

Text arrives when a message part completes. Tool parts arrive in a terminal state — input and output together — so one raw `tool_use` event produces both the `tool-call` and its `tool-result`. Each `step_finish` yields a `usage` event with that step's tokens and cost; `result.usage` carries the summed run totals.

## Errors

A typed `error` event in the stream (a bad model, a provider failure) throws [`AnyAgentError`](/docs/errors) with `code: "Invocation"` and opencode's own message. A nonzero exit throws the same code.

## Resume a session

The session id rides on `result.raw`:

```ts
const first = await agent.run("start reviewing this repo");
const { sessionId } = first.raw as { sessionId?: string };

const followUp = await agent.run("continue with src/", { resume: sessionId });
```
