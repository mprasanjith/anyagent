The `opencode` adapter drives the opencode CLI through `opencode run --format json`, detected as the `opencode` binary on `PATH`; import `opencode` from `anyagent/opencode`. opencode is bring-your-own-key (BYOK): it reads standard provider keys (`OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, …) from the environment, so it needs no subscription.

## What you can ask for

`readOnly`, `model` (as `"provider/model"`), `effort` (a provider-defined variant name, passed verbatim), `resume`, `forkSession`, and `attachments` all work on the CLI’s own switches. `systemPrompt` and `schema` work too, provided by AnyAgent. MCP is a config-file concern for opencode, reachable via [`extraArgs`](/docs/escape-hatches). The full grid is on the [support matrix](/docs/adapters).

`models()` runs `opencode models`, and every printed `provider/model` id is valid verbatim as `model`. `authStatus()` reads `~/.local/share/opencode/auth.json` plus the provider key env vars: a hint rather than a guarantee.

## Good to know

- Tool parts arrive in a terminal state, so one raw event produces both the `tool-call` and its `tool-result`; reasoning parts map to `reasoning-delta`.
- The session id is surfaced once, on first sight, and lands on `result.sessionId`.
- Usage arrives per step: each `step_finish` yields a `usage` event with that step’s share, including cache, reasoning, and cost, and `result.usage` carries the summed totals.

## Under the hood

Every run executes `opencode run --format json --auto` with the prompt piped over stdin. `--auto` is always passed: the default is the CLI’s maximum unattended autonomy, and `readOnly` confines it rather than dropping the flag. [Run options](/docs/api#run-options) append flags:

| Option           | Flag or env                                                 |
| ---------------- | ------------------------------------------------------------ |
| `readOnly: true` | env `OPENCODE_PERMISSION={"bash":"deny","edit":"deny"}`     |
| `model`          | `--model <provider/model>`                                  |
| `effort`         | `--variant <name>`                                          |
| `resume`         | `--session <sessionId>`                                     |
| `forkSession: true` | `--fork`, alongside `--session`, branching before continuing |
| `attachments`    | `-f <file>`, repeated once per attachment                  |

The adapter owns the `OPENCODE_PERMISSION` env var: a caller-supplied value under that key is overridden, so it can never weaken the read-only contract. The deny matrix uses category keys (the CLI silently ignores per-tool-name keys), and `webfetch` stays allowed: it reads the web and changes nothing on the machine. `auth list` is never run for `authStatus()`, because it exits 0 even with zero credentials.

opencode ships an ACP endpoint, `opencode acp`; see the [sessions guide](/docs/sessions).
