The `cline` adapter drives `cline --json --auto-approve true`, mapping Cline’s hook, agent-event, and run-result NDJSON stream onto AnyAgent’s normalized events. The Cline CLI is Apache-2.0 open source and BYOK: configure a provider once with `cline auth -p <provider> -k <key>` (openrouter, anthropic, openai, gemini, …), so it needs no subscription.

Import the factory from the `anyagent/cline` subpath and hand it to `create`:

```ts
import { create } from "anyagent";
import { cline } from "anyagent/cline";

const agent = create(cline());
const result = await agent.run("summarize this repo", {
  model: "openai/gpt-4o-mini",
});
```

## Detection

Detection looks for a `cline` binary on `PATH` and reads the version from `cline --version`. The version lands on [`DetectResult.version`](/docs/api#detectresult) for display only; behavior never depends on it.

## Capabilities

The adapter declares `mcp`, `sessionResume`, and the `read` permission level as unsupported, and provides `systemPrompt` and `structuredOutput` through core [emulation](/docs/api#capabilitysupport):

| Capability         | Value                          |
| ------------------ | ------------------------------ |
| `streaming`        | `native`, a live NDJSON stream |
| `permissionLevels` | `edit`, `auto`                 |
| `modelSelection`   | `native`                       |
| `sessionResume`    | `false`, broken upstream       |
| `mcp`              | `false`                        |
| `systemPrompt`     | `emulated`                     |
| `structuredOutput` | `emulated`                     |
| `cwd`              | `native`                       |

Two capabilities stay undeclared for honesty rather than convenience:

- **No `read`.** Cline’s plan mode still executes shell commands, verified writing a file through `run_commands`, so it cannot stand in for a read-only sandbox.
- **No `resume`.** `--id` is broken in Cline’s headless JSON mode: the prompt is never accepted alongside it, in any argument order.

Cline’s own `-s` replaces the system prompt entirely, which would break the append semantics `RunOptions.systemPrompt` promises. So a `systemPrompt` is `emulated` instead: the core folds it into the prompt text ahead of your prompt, preserving the append behavior on every agent. Reach `-s` via [`extraArgs`](/docs/escape-hatches) if full replacement is what you want.

```txt
<system-instructions>
{your system prompt}
</system-instructions>

{your prompt}
```

Structured output is `emulated` too: the core appends your schema to the prompt and parses the reply. See [Get structured output](/docs/structured-output).

## How options map to flags

Every run executes `cline --json --auto-approve true`. Your [run options](/docs/api#runoptions) append further flags:

| Option               | Flag                                   |
| -------------------- | -------------------------------------- |
| `permission: "edit"` | `--auto-approve true`                  |
| `permission: "auto"` | `--auto-approve true`, same invocation |
| `model`              | `-m <model>`                           |

Headless Cline auto-approves every tool. That is its own default; the adapter pins it explicitly so the behavior holds if the default ever changes, which makes `edit` and `auto` equivalent.

Two prompt quirks are upstream and the adapter cannot mask them: the prompt must be a positional argument because piped stdin is not read reliably, so a prompt larger than the OS argv limit needs [`agent.raw`](/docs/escape-hatches); and a single-word prompt is misparsed as a command name.

`cwd` and `env` are not flags: they become the spawned process’s working directory and extra environment variables. [`extraArgs`](/docs/escape-hatches) appends after every flag above, so a native flag there can override what `permission` set.

## What the stream produces

Text arrives whole per content block, so the answer is never double-counted against its partial deltas. Tool content maps to `tool-call` when the call is complete and `tool-result` when it returns.

Cline occasionally prints plain-text notices to stdout mid-stream (“AI SDK Warning …”). The adapter filters non-JSON lines before parsing, in strict mode too, because the notices are known Cline behavior rather than format drift.

## Usage reporting

Usage lands on [`RunResult.usage`](/docs/api#usage) with `inputTokens`, `outputTokens`, and `costUsd`. The final `run_result` yields the `usage` event with the run’s aggregate tokens and cost.

## Errors

A `run_result` with `finishReason` other than `"completed"` throws [`AnyAgentError`](/docs/errors) with `code: "Invocation"` and Cline’s own message. A nonzero exit or a spawn failure throws the same code.

## Resume a session

Cline does not support `resume`: `--id` is broken in its headless JSON mode upstream, so `sessionResume` is `false` and requesting `resume` throws [`AnyAgentError`](/docs/errors) with `code: "UnsupportedCapability"` before anything spawns. Continue a task by carrying context forward in the next prompt instead.
