This page shows how to send one prompt to an agent, tune the run with `RunOptions`, and read the `RunResult`. AnyAgent checks each capability-gated option (`permission`, `cwd`, `model`, `systemPrompt`, `resume`, `mcp`) against the agent’s capability table before any process spawns, so an unsupported request throws at the call site rather than mid-run.

Each example creates its agent from the `claude-code` adapter so the block runs as pasted. An `Agent` built from a detection result behaves the same; see [Detect installed agents](/docs/detecting-agents).

## Run a prompt and read the result

`agent.run(prompt, opts)` sends a prompt and resolves with a `RunResult` when the agent finishes. Here is the `acme init` wiring prompt, running with the default `edit` permission and an instruction to keep changes local:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const prompt =
  "Add the Acme SDK to this project: install the dependency, create " +
  "acme.config.ts with sensible defaults, and wire it into the app entry " +
  "point. Only edit files in this repo. Do not run git commit or git push.";

const result = await agent.run(prompt, { permission: "edit" });
console.log(result.text);
```

The agent’s final answer prints when the run finishes. The exact text varies by run:

```txt
Installed @acme/sdk, created acme.config.ts with project defaults, and
imported initAcme() in src/index.ts.
```

`RunResult` has four fields:

- `text`: the agent’s final answer, all text output concatenated
- `events`: every event in order, without the terminal `done`
- `usage`: token and cost accounting, when the CLI reports it
- `raw`: the CLI’s untouched final payload

Holding a `RunResult` means the run succeeded, because every failure throws instead. See [Handle errors](/docs/errors) for that path.

The `events` list is held in memory for the whole run. For a long agentic run, consume [`runStream`](/docs/streaming) as events arrive rather than collecting them all at the end.

## Write a scoped prompt

An agent does what the prompt tells it, so be specific. Name the files it should touch, state the goal, and say what to leave alone. The `acme init` prompt above names `acme.config.ts`, scopes changes to the repo, and forbids git commands.

Keep changes small and local. Never instruct the agent to commit or push, so the end user reviews the diff before anything reaches their history. Pair the prompt with a [permission](/docs/permissions) level that bounds what the agent can touch.

## Set the working directory

`cwd` sets the directory the agent works in. It defaults to the current process’s working directory. Point it at the target project when your tool runs from elsewhere:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
await agent.run("Summarize what this service does.", {
  cwd: "/home/sam/projects/acme-app",
  permission: "read",
});
```

Guard with `capabilities.cwd` when your tool targets more than one agent.

## Choose a model

`model` takes a name in the CLI’s own vocabulary; each [adapter page](/docs/adapters) shows how the option maps. Guard it with `capabilities.modelSelection` when the agent is not known in advance:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const opts = agent.capabilities.modelSelection ? { model: "opus" } : {};
await agent.run("Review the error handling in src/api/.", opts);
```

## Append a system prompt

`systemPrompt` is appended to the CLI’s own system prompt. It never replaces it. Use it to set standing instructions for the run:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
await agent.run("Add input validation to the signup form.", {
  systemPrompt: "Follow the Acme SDK conventions in docs/conventions.md.",
});
```

Guard with `capabilities.systemPrompt` when your tool targets more than one agent.

## Pass environment variables

`env` sets extra environment variables for the run, merged over the parent process’s environment rather than replacing it:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
await agent.run("Run the integration tests and fix any failures.", {
  env: { ACME_ENV: "development" },
});
```

## Resume a session

To continue a prior conversation, pass its session id as `resume`. The id lives on the previous run’s `raw` payload under a CLI-specific key, documented on each adapter page:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const review = await agent.run("Review this repo for unhandled rejections.");
const { session_id } = review.raw as { session_id?: string };

if (session_id) {
  await agent.run("Fix the issues you found.", { resume: session_id });
}
```

The `if` matters: `resume: undefined` does not throw, it starts a fresh session. Guard with `capabilities.sessionResume` when targeting an agent that might lack it.

## Attach MCP servers

`mcp` attaches Model Context Protocol servers for the run, keyed by the name the agent sees them under. Each entry sets `command`, `args`, and optional `env` for a local server, or `url` for a remote one:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
const opts = agent.capabilities.mcp
  ? { mcp: { db: { command: "npx", args: ["acme-db-mcp"] } } }
  : {};
await agent.run("Describe the database schema this app expects.", opts);
```

When a CLI routes MCP through its own config instead, its adapter page says so; reach it through [escape hatches](/docs/escape-hatches).
