title: Ship to production
description: What a shipped tool owes its end users, and the checklist to run before release.

A shipped tool runs a coding agent on a stranger’s machine, under their login, at their expense. This page states what that obligates your tool to do, and ends with the checklist to run before release. Each item links the guide that covers it in full.

## Nothing runs by surprise

Before any prompt runs, tell the end user which agent your tool found and what it is about to do, and ask which agent to use when several are installed. The run bills their subscription and edits their files; [Run agents](/docs/run-agents#choose-which-agent-to-run) shows the announce-and-choose flow.

Never let a shipped tool commit or push on the user’s behalf. Scope every prompt to name the files the agent may touch and forbid git, so the user reviews a diff instead of discovering history; [the prompt pattern](/docs/run-agents#run-a-prompt-and-read-the-result) shows how.

## Show progress and handle every failure

A run can take minutes, and a silent one looks hung: stream events to the user as the agent works, and wire an `AbortSignal` to Ctrl+C so cancelling is clean. [Stream progress](/docs/streaming) covers both.

Every failure throws `AnyAgentError` with one of four codes, so a `switch` on `err.code` is exhaustive error handling. Give each code a message a stranger could act on, and log `argv` and `stderr` on `Invocation` failures so bug reports are actionable. [Handle errors](/docs/errors#turn-each-code-into-a-message-for-the-end-user) has the full branch-by-branch example.

## Before you ship

- Detect first, and handle the none-installed case with a message that names a supported CLI and its setup steps
- Tell the user which agent runs and that it draws on their login and subscription
- Ask which agent to use when more than one is installed
- Scope the prompt: name the files, keep changes local, forbid commits and pushes
- Run at `permission: "edit"` for tools that change code, `read` for analysis, never `auto` outside a sandbox
- Handle all four error codes with messages a stranger can act on
- Bound run time with `AbortSignal.timeout` so a hung CLI cannot hang your tool
- Pin nothing to agent versions; `version` is for display, and AnyAgent targets current CLIs
- Test with each supported CLI installed and with none, using a [fake probe](/docs/run-agents#test-without-a-cli) in CI
- Log `argv` and `stderr` on failure so users can file useful bug reports
