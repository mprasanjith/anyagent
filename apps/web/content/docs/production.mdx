This guide assembles the recommended flow for a tool you ship to end users: detect, announce, choose, run with visible progress, handle every error code. The running example is `acme init`, a setup wizard that wires the fictional Acme SDK into the end user’s project. Each step links its own guide for the full detail.

## Detect what the user has installed

`detect()` scans the end user’s `PATH` and returns one `DetectResult` per installed agent. The order carries no preference, and an empty array means no supported agent is installed.

```ts
import { detect } from "anyagent";

const found = await detect();
```

Each result carries `id`, `name`, `version` (display only), `path`, `capabilities`, and the `adapter`; pass the one you pick straight to `create()`.

## Tell the user what is about to happen

Before running anything, state which agent you will use. The prompt executes on the user’s machine, under their login, and may make model calls they pay for, so nothing should run by surprise.

```ts
import type { DetectResult } from "anyagent/types";

const announce = (chosen: DetectResult): void => {
  console.log(`acme init will use ${chosen.name} (${chosen.path}).`);
  console.log("It runs on your login and your subscription.");
};
```

## Let the user choose when several are installed

When `detect()` returns more than one agent, ask which to use rather than picking for them. One result means use it; none means fall back or point at install docs.

```ts
import { create } from "anyagent";
import type { Agent, DetectResult } from "anyagent/types";
import { createInterface } from "node:readline/promises";

const pickAgent = async (found: DetectResult[]): Promise<Agent | null> => {
  const [first] = found;
  if (!first) {
    console.error(
      "acme init needs a coding agent. Install a supported CLI, sign in, and rerun."
    );
    return null;
  }
  if (found.length === 1) {
    return create(first);
  }
  const rl = createInterface({ input: process.stdin, output: process.stdout });
  found.forEach((a, i) => console.log(`${i + 1}. ${a.name}`));
  const answer = await rl.question("Which agent should acme init use? ");
  rl.close();
  return create(found[Number(answer) - 1] ?? first);
};
```

If the agent is a hard requirement, the empty case should name a [supported agent](/docs/adapters) and point to its install docs rather than failing silently. [Detect installed agents](/docs/detecting-agents) shows richer selection and fallback patterns.

## Run with visible progress and a scoped prompt

Stream the run so the user sees work as it happens, and scope the prompt so the agent stays local. `runStream` yields `text-delta` events to render live and ends with a `done` event carrying the final `RunResult`.

```ts
import type { Agent } from "anyagent/types";

const runInit = async (agent: Agent): Promise<string> => {
  const prompt = [
    "Add the Acme SDK to this project.",
    "Only edit package.json and files under src/.",
    "Do not run git, do not commit, do not push.",
    "Create src/acme.ts with an initialized client and wire it into src/index.ts.",
  ].join(" ");

  let answer = "";
  for await (const event of agent.runStream(prompt, { permission: "edit" })) {
    if (event.type === "text-delta") {
      process.stdout.write(event.text);
    }
    if (event.type === "done") {
      answer = event.result.text;
    }
  }
  return answer;
};
```

The prompt does the guardrail work: it names the exact files the agent may touch, keeps the change local, and forbids commits and pushes. Never let a shipped tool commit or push on the user’s behalf; leave the diff for the user to review. Run at `edit`, the default; see [Permissions](/docs/permissions) for choosing a level and [Stream progress](/docs/streaming) for progress and cancellation.

## Handle every error code

Every failure throws `AnyAgentError` with one of four codes. Branch on `.code` and give a message a stranger could act on. Cancellation through an `AbortSignal` is not a failure, so return quietly on `"Aborted"`. `runInit` here is the streaming runner from the previous step.

```ts
import { AnyAgentError } from "anyagent/errors";
import type { Agent } from "anyagent/types";

const runWithHandling = async (agent: Agent): Promise<void> => {
  try {
    await runInit(agent);
  } catch (err) {
    if (!(err instanceof AnyAgentError)) {
      throw err;
    }
    switch (err.code) {
      case "Aborted":
        return;
      case "UnsupportedCapability":
        console.error(
          "This agent cannot do what acme init asked. Try another installed agent."
        );
        return;
      case "Invocation":
        console.error(
          "The coding agent failed to run. Check that it is signed in."
        );
        console.error(err.argv?.join(" "), err.stderr);
        return;
      case "Parse":
        console.error(
          "The agent produced output acme init could not read. Please report this with the log above."
        );
        console.error(err.argv?.join(" "), err.stderr);
        return;
      default:
        throw err;
    }
  }
};
```

`argv` and `stderr` are attached whenever a process was involved, so log them on `"Invocation"` and `"Parse"` to make bug reports actionable. [Handle errors](/docs/errors) details each code and when it fires.

## Before you ship

Run through this list before releasing a tool built on AnyAgent:

- Detect first, and handle the none-installed case with a message that names a supported CLI and its setup steps
- Tell the user which agent runs and that it draws on their login and subscription
- Ask which agent to use when more than one is installed
- Scope the prompt: name the files, keep changes local, forbid commits and pushes
- Run at `permission: "edit"` for tools that change code, `read` for analysis, never `auto` outside a sandbox
- Handle all four error codes with messages a stranger can act on
- Pin nothing to agent versions; `version` is for display, and AnyAgent targets current CLIs
- Test with each supported CLI and with none installed
- Log `argv` and `stderr` on failure so users can file useful bug reports
