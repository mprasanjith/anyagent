This page shows how to find the agents installed on the end user’s machine, pick one to run, and handle a machine with none.

## Find what is installed

Call `detect()` to scan the end user’s `PATH` for every supported agent. It returns one `DetectResult` per installed agent, and an empty array when none are found:

```ts
import { detect } from "anyagent";

const installed = await detect();
for (const found of installed) {
  console.log(`${found.name} ${found.version ?? "unknown"} at ${found.path}`);
}
```

On a machine with Claude Code and Codex installed, this prints:

```txt
Claude Code 2.0.31 at /home/sam/.local/bin/claude
Codex 0.48.0 at /usr/local/bin/codex
```

## Choose which agent to run

The order of results carries no preference, and there is no “best” agent, so which one to run is your product decision. This picker prints the options and reads a choice from stdin:

```ts
import { create, detect } from "anyagent";
import { createInterface } from "node:readline/promises";

const installed = await detect();
const [first] = installed;
if (!first) {
  throw new Error("No supported coding agent found.");
}

const rl = createInterface({ input: process.stdin, output: process.stdout });
installed.forEach((a, i) => console.log(`${i + 1}. ${a.name}`));
const answer = await rl.question("Which agent should acme init use? ");
rl.close();

const chosen = installed[Number(answer) - 1] ?? first;
const agent = create(chosen);
```

`create()` accepts a `DetectResult` directly and returns a runnable `Agent`. The prompt looks like this:

```txt
1. Claude Code
2. Codex
Which agent should acme init use? 1
```

## Tell the user what will happen

Before you run anything, name the agent and describe the task you are about to drive. The prompt runs under the user’s login and bills against their subscription, so nothing should run by surprise.

```ts
import { detect } from "anyagent";

const [chosen] = await detect();
if (!chosen) {
  throw new Error("No supported coding agent found.");
}

console.log(
  `acme init will run ${chosen.name} to set up the Acme SDK on your codebase.`
);
```

## Handle an empty machine

When `detect()` returns an empty array, no supported agent is installed. Your response depends on whether the agent is a hard requirement.

When the agent adds an optional feature, degrade gracefully, skip it, and continue with your manual path:

```ts
import { detect } from "anyagent";

const installed = await detect();
if (installed.length === 0) {
  console.log("No coding agent found. Skipping automatic setup.");
}
```

When the agent is required, tell the user which CLIs you support, naming them from the [supported agents](/docs/adapters), and how to install one:

```ts
import { detect } from "anyagent";

const installed = await detect();
if (installed.length === 0) {
  console.error(
    "acme init needs a coding agent. Install a supported CLI, sign in, and rerun."
  );
  process.exit(1);
}
```

## Target one specific agent

When your tool supports exactly one agent, skip detection and import that adapter directly. Subpath imports pull in only the adapter you use:

```ts
import { create } from "anyagent";
import { claudeCode } from "anyagent/claude-code";

const agent = create(claudeCode());
```

Every adapter imports the same way from its own subpath, named on its adapter page. Creating an agent from an adapter does not check whether the CLI is installed, so a missing binary surfaces as an `Invocation` error when you run. See [Handle errors](/docs/errors).

## Adjust to an agent’s capabilities

Each `DetectResult` carries a `capabilities` table describing what its CLI can do. Read it before you decide what to ask for, so the same code works across agents with different feature sets:

```ts
import { create, detect } from "anyagent";

const [found] = await detect();
if (!found) {
  throw new Error("No supported coding agent found.");
}

const agent = create(found);
const opts = found.capabilities.mcp
  ? { mcp: { db: { command: "npx", args: ["acme-db-mcp"] } } }
  : {};
await agent.run("Describe the database schema this app expects.", opts);
```

Requesting an unsupported capability throws before the CLI spawns. Each adapter page lists the capability table its CLI declares.
